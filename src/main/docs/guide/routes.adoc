=== Java DSL

Every bean of type `RoutesBuilder`, such as a `RouteBuilder`, `EndpointRouteBuilder` or `RouteConfigurationBuilder`, is added to Camel when the application starts. Route builders are created after the `CamelContext` bean, so they can inject it, the Camel templates, and any other bean:

snippet::io.micronaut.camel.docs.routes.PriceService[tags="service", indent=0, title="A service"]

snippet::io.micronaut.camel.docs.routes.PriceRoutes[tags="routes", indent=0, title="A route calling the service"]

<1> The route builder receives the service through its constructor.
<2> The route invokes the `priceOf` method of the service (`price_of` in Python).

Routes can also be declared as lambdas, with `LambdaRouteBuilder`, or with `LambdaEndpointRouteBuilder` for the type-safe https://camel.apache.org/manual/Endpoint-dsl.html[Endpoint DSL], which needs the `camel-endpointdsl` dependency:

snippet::io.micronaut.camel.docs.routes.ShippingRoutes[tags="routes", indent=0, title="Lambda routes"]

<1> A route written with the Java DSL.
<2> A route written with the Endpoint DSL.

The `camel.main.java-routes-include-pattern` and `camel.main.java-routes-exclude-pattern` options select which route builder classes are added.

==== Kotlin, Groovy and Python

Camel removed its Kotlin DSL in Camel 4, so Kotlin routes, like Groovy and Python (Pyronaut) routes, use the Java DSL, as the samples of this guide show. Some method names of the Java DSL are keywords of these languages:

snippet::io.micronaut.camel.docs.routes.ParcelRoutes[tags="routes", indent=0, title="Methods of the Java DSL named like keywords"]

<1> `when` is a Kotlin keyword: call the `when` of `choice()` with backticks, `++`when`(...)++`.
<2> So is `in`, the predicate of `ValueBuilder` matching one of several values: `++`in`(...)++` in Kotlin, `in_(...)` in Python, where `in` is a keyword too.
<3> In Kotlin strings, escape the `$` of Camel's `${...}` expressions, as in `"\${header.country}"`.

In Python, the `from` method of a route builder is `from_`, and the other keywords of the Java DSL get the same trailing underscore, such as `in_`; `when` is not a Python keyword. Groovy needs no escaping, as long as Camel expressions are in single-quoted strings, which Groovy does not interpolate.

=== YAML DSL

With the `camel-yaml-dsl` dependency, Camel loads the YAML routes found by `camel.main.routes-include-pattern`, which by default is `classpath:camel/*,classpath:camel-template/*,classpath:camel-rest/*`:

dependency:org.apache.camel:camel-yaml-dsl[]

[source,yaml]
.src/main/resources/camel/notifications.yaml
----
include::test-suite/src/test/resources/camel/notifications.yaml[tags=routes]
----

YAML routes call Micronaut beans by name, as described in <<beans, Beans and the Camel Registry>>.

=== XML routes

XML routes, which Camel loads with the XML DSL of `camel-xml-io-dsl`, and Spring XML contexts are not supported: write the routes with the Java DSL or the YAML DSL. When `camel.main.routes-include-pattern` matches XML files, the application fails to start with a message that names the files:

----
XML routes are not supported by Micronaut Camel: camel.main.routes-include-pattern (classpath:camel/*) matches classpath:camel/orders.xml. Write the routes with the Java DSL, as RouteBuilder beans, or with the YAML DSL (camel-yaml-dsl), or exclude the XML files from camel.main.routes-include-pattern
----

Without the check, Camel would only report that it cannot find a `RoutesBuilderLoader` for the `xml` file extension. To keep XML files next to the routes, for example for another tool, exclude them with `camel.main.routes-exclude-pattern`, or narrow the include pattern, such as `classpath:camel/*.yaml`.
