Routes are tested with `@MicronautTest`: the test starts the application context, and so Camel. The Camel templates and Camel's `MockEndpoint` and `NotifyBuilder` work as usual.

The `micronaut-camel-test` dependency adds the annotations of Camel's Spring Boot test support to `@MicronautTest` tests:

dependency:io.micronaut.camel:micronaut-camel-test[scope="testImplementation"]

snippet::io.micronaut.camel.docs.testing.MockGreetingsTest[tags="test", indent=0, title="Mocking endpoints"]

<1> Messages sent to the endpoints matching `log:*` are also sent to a mock endpoint.
<2> The mock endpoint of `log:greetings` is `mock:log:greetings`.

[cols="1,2"]
|===
|Annotation |Effect

|`@MockEndpoints`
|Messages sent to the matching endpoints are also sent to `mock:<endpoint uri>`

|`@MockEndpointsAndSkip`
|Messages sent to the matching endpoints are only sent to `mock:<endpoint uri>`

|`@ExcludeRoutes`
|The given route builder classes are not added

|`@AutoStartupExclude`
|The matching routes are not started

|`@UseAdviceWith`
|Camel is not started, so the test can change routes with `AdviceWith` and then call `camelContext.start()`

|`@ShutdownTimeout`
|How long Camel waits for in-flight messages when the test stops. Tests use 10 seconds by default.

|`@EnableRouteCoverage`
|The route coverage of the test is written to a file when Camel stops, as described below
|===

The annotations are read from the annotation metadata of the test class, so they also apply to Python tests.

==== Route coverage

`@EnableRouteCoverage` dumps the route coverage of a test: how many exchanges each route, and each processor of a route, processed. It needs Camel's JMX management, so add `camel-management`, and leave `camel.main.jmx-enabled` to its default, `true`:

dependency:org.apache.camel:camel-management[scope="testImplementation"]

snippet::io.micronaut.camel.docs.testing.GreetingCoverageTest[tags="test", indent=0, title="Dumping the route coverage"]

<1> The route coverage is dumped when Camel stops, after the tests of the class.
<2> The `greet` route processes one exchange.

The coverage is written to `build/camel-route-coverage/<test class>-<test method>.xml` (with `_` for the characters of the name other than letters, digits, `.`, `_`, `-` and `$`, such as those of Spock feature names), or to `target/camel-route-coverage` in a Maven project, in the format of Camel's own test support, which tools such as the `route-coverage` goal of the `camel-report-maven-plugin` read. As the tests of a class share the application context, and so Camel, the file holds the coverage of all the tests of the class, and is named after the last one. Set `micronaut.camel.test.route-coverage.directory` to write the files elsewhere.
