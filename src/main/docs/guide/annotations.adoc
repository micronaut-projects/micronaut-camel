Camel's bean annotations, such as `@EndpointInject`, `@Produce` and `@Consume`, work on Micronaut beans. In Java and Kotlin, the Micronaut Camel annotation processor turns them into Micronaut injection points and executable methods at compile time, so Camel does not inspect beans by reflection at runtime. Add it to the annotation processor path of your build:

dependency:io.micronaut.camel:micronaut-camel-processor[scope="annotationProcessor"]

[cols="1,2"]
|===
|Annotation |Effect

|`@EndpointInject("uri")`
|Injects the endpoint, or a `ProducerTemplate`, `FluentProducerTemplate`, `ConsumerTemplate`, `Producer` or `PollingConsumer` for it, into a field, a setter or a constructor parameter

|`@Produce("uri")`
|Injects a template for the endpoint, or a proxy of an interface whose method calls send messages to it

|`@Consume("uri")`
|Subscribes the method of a singleton bean to the endpoint when Camel starts. The `predicate` attribute filters the messages.

|`@BeanInject("name")`
|Injects the bean with that name, like `@Named`

|`@PropertyInject("key")`
|Injects the value of a property, with an optional `defaultValue`, like `@Value`

|`@BindToRegistry("name")`
|On a class, makes it a singleton bean with that name

|`@Converter`
|On a class, registers its `@Converter` methods with Camel's type converters
|===

NOTE: `@EndpointInject` and `@Produce` need the endpoint URI: resolving it from a property of the bean is not supported. `@BindToRegistry` is supported on classes only; declare other beans with a `@Factory`.

NOTE: In Groovy, the annotation processor cannot generate code, so Camel applies its annotations to the beans that use them at runtime, by reflection, as in Spring Boot. Add `micronaut-camel-processor` to the `compileOnly` configuration, and `micronaut-camel-test` for the annotations of Spock specifications.
